## 构建环境

这些版本来自仓库里的 Gradle 文件：

| 项目 | 版本 |
| --- | --- |
| Gradle Wrapper | 8.13 |
| Android Gradle Plugin | 8.13.2 |
| Kotlin | 2.2.21 |
| Java 字节码 | 17 |
| 编译 / 目标 SDK | 36 |
| Build-Tools | 36.0.0 |
| 最低 SDK | 29 |
| `applicationId` | `com.fanyi.overlay` |
| `versionName` / `versionCode` | `0.1.0` / `2` |

JDK 使用 17，或使用能把 Kotlin 编到 JVM 17 的 JDK 21。`gradle.properties` 里有 `android.builder.sdkDownload=false`，Gradle 不会自己下载 Android SDK。需要事先装好 Platform 36 和 Build-Tools 36.0.0。

`local.properties` 已在 `.gitignore` 里，不要提交。keystore、`*.p12`、`signing.properties`、`keystore.properties` 和口令文件也不要提交。

debug 包仍由本机 Android SDK 的调试证书签名，不需要发布密钥。`assembleRelease` 只接受仓库外的签名配置：环境变量 `FUYI_SIGNING_PROPERTIES` 指向一份 properties，或同时设置 `FUYI_STORE_FILE`、`FUYI_STORE_PASSWORD`、`FUYI_KEY_ALIAS`、`FUYI_KEY_PASSWORD`。properties 里的 `storeFile` 可以相对该文件所在目录。没有这些配置时，正式构建会直接失败，不会改用 debug 证书。不要把口令或密钥路径写进仓库。

当前还没有已发布的 GitHub Release。正式包和 debug 包证书不同。

## Android Studio

用 Android Studio 打开含有 `settings.gradle.kts` 的仓库根目录。在 SDK Manager 里安装 Android 36 和 Build-Tools 36.0.0，并让 Studio 使用 JDK 17 或 21。同步时 Studio 会写好本机的 `local.properties`。

运行配置选择 app 的 debug。单元测试任务是 `:app:testDebugUnitTest`。

## 命令行

Linux 和 macOS：

```bash
export ANDROID_HOME="$HOME/Android/Sdk"
printf 'sdk.dir=%s\n' "$ANDROID_HOME" > local.properties
chmod +x ./gradlew
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

`ANDROID_HOME` 换成你机器上的 SDK 目录。Android Studio 的默认位置通常是上面的路径。

Windows PowerShell：

```powershell
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$sdk = $env:ANDROID_HOME -replace '\\','/'
"sdk.dir=$sdk" | Set-Content -Encoding ascii local.properties
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest
```

这里把路径写成正斜杠，避免 `local.properties` 把反斜杠当成转义。如果任务仍然找不到 SDK，用 Android Studio 打开一次，让它重写 `local.properties`。

debug APK 在 `app/build/outputs/apk/debug/app-debug.apk`。`build/`、`.gradle/` 和 APK 都已被忽略，不要加进提交。

## 运行时结构

听写从 `CaptureService` 进入 `PlaybackCapturer`，再进入 `CaptionPipeline`。流水线按 `asrProvider` 创建其中一个类：

- `asr/VolcengineAsrClient.kt`
- `asr/AliyunAsrClient.kt`
- `asr/TencentAsrClient.kt`

三者都实现 `asr/Asr.kt` 里的 `StreamingAsr`。翻译由 `translate/ExtraTranslators.kt` 的 `textTranslator()` 选择 `VolcengineTranslator`、`AliyunTranslator`、`TencentTokenHubTranslator`、`TencentTranslator` 或 `OpenAiTranslator`。取消走 `Net.http.executeCancellable`，新的一句可以丢掉还没返回的旧请求。

语言和缺字段的判断在 `model/VendorSupport.kt`。设置页是 `ui/settings/SettingsScreen.kt`。保存的键名在 `data/SettingsStore.kt`。

`model/Models.kt` 里的 `volcAk`、`volcSk` 和 `volcMode` 会随配置读写，但当前设置页没有对应输入，识别和翻译实现也不读取它们。不要在文档里把它们写成用户可见开关。

## 接入一家新的云服务

1. 在 `Provider` 里增加枚举，并在 `parseStoredVendor` / `vendorWire` 里接上稳定的存储字符串。旧配置没有新字段时会回退到旧的 `provider`。
2. 识别实现 `StreamingAsr` 的 `start`、`sendPcm` 和 `finish`，通过 `AsrEvents` 交回原文。在 `CaptionPipeline` 里按 `asrProvider` 创建它。OpenAI 兼容没有识别实现，也不要把它接成识别。
3. 翻译实现 `TextTranslator.translate`，在 `textTranslator()` 里创建。
4. 在 `VendorSupport` 里写明缺哪些字段、哪些来源语言不能用。不能用时返回中文说明。不要改写用户选的语言，也不要在失败时调用另一家。
5. 在设置页增加对应输入框。密钥沿用现有加密存储，不要写进日志，不要写进仓库。
6. 用固定的假密钥、签名向量或一段假 JSON 做单元测试。没有真实账号就不要发网络请求。
